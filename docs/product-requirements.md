# 全新项目：学生发展测评与发展报告
# New Clean Project / Student-Only

我要重新建立一个全新的项目。

这不是在旧项目上继续修改。

旧项目只作为：
- UI 视觉参考
- 已验证交互组件参考
- 技术实现参考

不要把旧项目中的 Parent / Dual Perspective / 旧题库 / 旧 Prompt / 旧状态机直接迁移进新项目。

这是一个全新的 Student-Only 产品。

我会同时上传一份我已经修改完成的最新测评题库文件。

该文件是新项目正式测评题库的唯一 source of truth。

==================================================
一、核心产品流程
==================================================

整个学生端只有三个非常明确的阶段：

① 完成测评
→
② 补充个人信息
→
③ 生成结果

不要使用过于抽象的阶段名称。

不要使用：

认识自己
完善自己
探索未来

作为主流程名称。

用户必须一眼知道自己现在正在做什么。

页面顶部可以持续显示：

完成测评
1 / 3

→

补充个人信息
2 / 3

→

生成结果
3 / 3

或者采用同等清晰、极简的 progress indicator。

B.
提供给升学指导师进一步分析使用的：

==================================================

==================================================
十二、全流程进度必须从一开始就明确
==================================================

这是非常重要的产品要求。

之前测试发现：

用户做完测评
→ 看见结果
→ 认为产品已经结束
→ 直接退出

但真正重要的信息收集和后续分析还没有发生。

因此从测评开始，就要让用户知道：

测评只是第一阶段。

持续显示清晰流程：

① 完成测评
② 补充个人信息
③ 生成结果

例如：

完成测评 ●
补充个人信息 ○
生成结果 ○

不要让“做完题”产生最终完成感。

这可能是一个值得继续观察的发展线索……
可以结合真实经历进一步看看……

报告用于：

帮助学生观察自己

而不是：

==================================================
二十二、个人信息内容
==================================================

A. 基础学习情况
- 年级
- 学校（如需要）
- 当前课程体系（如需要）

B. 学业表现
- 主要学科
- 成绩 / 大致表现
- 比较有把握的学科
- 相对有挑战的学科

C. 真实经历
- 项目
- 比赛
- 社团
- 课外活动
- 志愿活动
- 兴趣活动
- 长期坚持的事情

D. 当前兴趣
- 最近特别感兴趣的领域
- 愿意主动投入时间的事情

E. 未来探索
- 已经考虑过的专业
- 感兴趣的职业
- 想进一步了解的方向
- 如果完全不知道，也允许填写“不确定”

F. 现实考虑
如产品确实需要，可以提供：
- 地区
- 大学环境偏好
- 家庭考虑
- 其他现实因素

不要要求学生必须知道未来要做什么。

==================================================
三十、《我的发展报告》建议结构
==================================================

根据新题库最终结构适配，不要硬套旧维度。

建议：

01
现在的我

简洁总结当前发展画像。

02
我的发展特点

结合测评结果解释主要发展线索。

03
我的兴趣与投入

结合学生真实填写的信息，
看哪些事情真正吸引学生投入。

04
我的学习方式

结合测评 + 学业信息，
描述学生目前呈现出的学习特点。

05
我的能力信心与真实经历

如果题库中包含能力信心相关内容，
要区分：

“我相信自己能做到”

和：

“我已经通过经历证明自己做过”

不要混为一谈。

06
我的经历告诉了我什么

结合：

项目
比赛
社团
活动
长期兴趣

寻找可以进一步观察的发展线索。

07
值得继续探索的问题

不要急着给答案。

提出几个真正值得学生继续探索的问题。

08
下一步

给学生一些简单可执行的探索建议。

整个产品遵循：

ONE PRIMARY ACTION

未测评：

开始测评 →

测评中：

继续测评 →

测评完成：

看看我的测评结果 →

画像看完：

继续补充个人信息 →

个人信息进行中：

继续填写 →

个人信息完成：

生成我的发展报告 →

结果完成：

查看我的发展报告 →

不要同时出现多个同等级主 CTA。

==================================================
四十、视觉要求
==================================================

视觉继续保持我之前喜欢的方向：

- Apple-like
- 极简
- 大量留白
- 浅背景
- Lovable 风格柔和渐变
- 蓝 / 紫 / 青 / 少量粉色
- 圆角
- 克制阴影
- 精致
- 不儿童化
- 不像传统心理测评网站
- 不像后台管理系统

报告页也保持同一视觉语言。

==================================================
四十一、不要过度使用卡片
==================================================

不要所有内容都放在大 Card 里面。

保持页面呼吸感。

优先使用：

Typography
Whitespace
Hierarchy
Subtle divider
Light gradient

而不是大量 box。

==================================================
四十二、Mobile First 检查
==================================================

必须测试手机端。

尤其检查：

- Hello
- 题目
- 1–5 作答
- progress
- textarea
- 个人信息 onboarding
- report
- download

不能只在 desktop 好看。

==================================================
四十三、可访问性
==================================================

至少保证：

- keyboard navigation
- visible focus
- readable contrast
- semantic labels
- reduced motion support
- reasonable tap targets

==================================================

- Invitation Code
- QR

这些之后单独做。

==================================================
四十五、实施顺序
==================================================

不要一次把所有页面写完。

按照以下 Milestone：

MILESTONE A

Question Bank
→ Assessment
→ Scoring
→ 我的发展画像

完成后验证。

MILESTONE B

补充个人信息
→ 自动保存
→ Development Context

完成后验证。

MILESTONE C

《我的发展报告》
→ Final Result Page
→ Download

完成后验证。

MILESTONE D

只为未来《导师分析资料》准备 structured data interface。

不写 Prompt。

==================================================
四十六、Milestone A 必须先通过
==================================================

在继续 B/C 前，必须验证：

1. 最新题库总数正确
2. 第一题正确
3. 最后一题正确
4. item ID 正确
5. dimension mapping 正确
6. scoring 正确
7. reverse scoring 正确（如有）
8. profile 能生成
9. refresh 能恢复
10. Testing Mode 使用同一 pipeline

如果 A 没有通过，不要继续堆后面的功能。
